# Guide — 03 : Suivi Tracking public et privé

**Périmètre :** `D:\AlloDelevry\backend`
**Entrées (routes) :**
- `GET /api/tracking/{privateToken}` (**publique**, sans authentification, `throttle:60,1`) — page de suivi du destinataire (F11)
- `apiResource delivery-proofs` : `GET/POST/PUT/PATCH/DELETE /api/delivery-proofs[/{id}]` (`auth:sanctum`) — preuves (F14)
- `apiResource request-status-histories` **only** `index/show` : `GET /api/request-status-histories[/{id}]` (`auth:sanctum`) — historique de statuts, lecture seule (F10)
**Référence cahier des charges :** F11 (lien privé de suivi), F14 (preuves et code sécurisé), F10 (workflow de statuts / historique)

## Vue d'ensemble

Chaque demande de livraison possède un **jeton privé** (`private_token`, 32 caractères aléatoires) qui sert de lien de suivi secret : `GET /api/tracking/{token}` renvoie, **sans authentification**, tout le contexte F11 — numéro de suivi, statut courant, adresses, expéditeur (client), livreur + marque, service, zone, timeline complète des statuts, les 20 derniers messages du chat et les preuves de livraison. La ressource `PublicTrackingResource` est la pièce maîtresse : elle est construite exclusivement sur des relations *eager-loadées* dans `DeliveryRequestController::tracking()` et **ne laisse fuiter aucune donnée sensible** (`private_token`, `confirmation_code_hash` — vérifié par test). Les deux volets annexes : l'**historique de statuts** (`request_status_histories`, alimenté uniquement par `DeliveryRequest::transitionTo()`, exposé en lecture seule — les routes d'écriture ont été supprimées en AR-05/B3) et les **preuves de livraison** (`delivery_proofs`, uploads réels d'images par le driver, fichiers publics sur le disque `public`). Le tracking a été complété en AR-37 (chat, preuves, infos livreur) ; la position GPS reste volontairement exclue (bonus ultérieur).

## Pièges et points d'attention

- **Le jeton de suivi est un secret d'URL** : `GET /tracking/{token}` est public — quiconque possède le token accède au suivi. Le token est 32 caractères aléatoires (`Str::random(32)`), non exposé par les ressources, mais **il transite par l'URL** : à éviter dans les logs, à transmettre par canal privé (chat/QR).
- **Rate limiting spécifique** : `throttle:60,1` sur `/tracking/{token}` (et les routes publiques `/drivers/{slug}`) — vérifié empiriquement à 429 dès 61 requêtes/minute (AR-05). Protège le 404-scanner du endpoint public.
- **Réponse enveloppée dans `data`** : `tracking()` renvoie un `JsonResource` (pas `success()`), donc le frontend lit `data.*` — les tests l'exploitent via `assertJsonPath('data.timeline.0.new_status', ...)`.
- **Eager-loads obligatoires** : chaque bloc de `PublicTrackingResource` est sous `whenLoaded()`. Si `tracking()` oublie une relation, la section correspondante disparaît silencieusement de la réponse (ex. `driver.driverProfile` pour `brand_name`).
- **Double protection anti-fuite** : `$hidden` sur le modèle (JSON direct) **et** `toArray()` explicite de la ressource (API). Les deux sont testés (`assertJsonMissingPath`). Ne pas exposer `private_token`/`confirmation_code_hash`/email dans de futures évolutions.
- **Historique 100 % read-only** : écrit uniquement par `transitionTo()` ; `POST/PUT/DELETE /request-status-histories` → 405 (B3). Ne jamais recréer ces routes : l'audit serait falsifiable.
- **Preuve requise avant `livree`** (RG06) : `confirmDelivery()` vérifie `proofs()->count() === 0` → 422. Le tracking n'affichera donc des preuves qu'après leur dépôt par le driver (statuts `colis_recupere`/`en_livraison`/`livree`).
- **`file_url` dépend du lien symbolique `public/storage`** : `asset('storage/...')` → `php artisan storage:link` déjà exécuté (AR-30) ; à refaire sur chaque nouvel environnement de déploiement.
- **La suppression d'une preuve ne supprime pas le fichier disque** : `DeliveryProofController::destroy()` supprime la ligne DB mais pas le fichier (seul `update()` avec remplacement purge l'ancien fichier) — trou de nettoyage connu, faible impact.
- **GPS volontairement exclu** (décision utilisateur) : F11 mentionne « dernière position autorisée » mais la position GPS est un bonus à implémenter plus tard ; `PublicTrackingResource` ne la renvoie pas.
